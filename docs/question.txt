目前我认为有问题或者需要优化的点有：
1. 上下文工程不太合理
    目前上下文的设计其实就是从数据库中读取最近的n条消息，然后进行拼接。这就导致有几个问题，比如：agent不知道过去发生的事情，只知道近段时间发生的事情
    我认为一个合理的上下文应该包括：system prompt、长期记忆的压缩摘要、长期自定义指令、短期记忆、用户画像、agent执行过程中的状态、工具调用、用户输入
    当然，意图识别的上下文其实可以精简一下，因为他可能不需要关心过去很久的事情，只需要知道最近的事情。
    可以引入context manager，负责上下文的管理
2. 意图识别责任不清晰
    目前意图识别模块做的事情包括：识别意图、是否执行工具调用、获取工具调用参数
    识别意图和获取工具调用参数应该分开，因为获取工具调用参数需要调用工具，而识别意图不需要调用工具
    意图识别应该仅做intent识别，其他事情应该交给其他模块处理
3. 工具协议没有统一
    现在应该统一工具协议：
    所有工具继承 `BaseTool`，核心契约为：
    - `name`：模型调用的唯一名称；
    - `description`：决定模型何时选择工具；
    - `parameters`：JSON Schema 参数定义；
    - `execute(**kwargs) -> ToolResult`：异步执行入口；
    - `to_openai_schema()`：转为 Function Calling Schema。
4. agent对于llm的调用是单步的，固定工作流，没有对轮思考
    我认为当前agent应该是react模型，反复迭代思考，得到最终的结果。因为用户的一个查询往往是多个动作执行后的结果，比如用户想先确定购物车是否有这样的订单然后再下单，
    这就涉及到了多个工具调用，同时llm也应该先验证某个工具调用结果再执行下一个工具调用。有时候工具调用又是可以并发的，相互没有依赖。
5. 上下文会对工具调用结果进行拦截
    工具返回的结构化数据（商品 ID、订单号等）可能被截断，导致后续无法进行准确推理。
