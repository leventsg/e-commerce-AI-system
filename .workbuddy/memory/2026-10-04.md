## 探讨：sandbox 真实执行 + 数据快照边界（未实现，方案已定）

用户问：重放校验能不能用 sandbox 让写操作也真实执行（当前写操作只记录意图、不真发 RPC）。结论：
- **执行底座光谱**（已画图）：内存模拟（写=改内存 map，验证策略语义）→ Sandbox 真实执行（写=真写隔离库，验证数据行为）→ 生产灰度（写=真写生产，验证真实效果）。当前在「内存模拟」，用户要的是中间那档。
- **sandbox 三件套**：① 隔离服务栈（独立 MySQL database / Redis db index，绝不写生产库）；② 数据快照导入（起始状态灌库，非实时活库）；③ 状态重置（每次 trial 前 TRUNCATE，防写操作叠加）。
- **项目现状**：docker 全开，真实 RPC handler 本就在；改动集中在 `evaluation.go` 的 handler 替换那处 + sandbox 环境管理，不动业务逻辑。建议先做方案 A（最小 sandbox，打通 order_create 真实执行）。
- **数据快照边界（关键认知）**：当前 `buildFixtureFromTrace` 存的是「轨迹里读工具返回的结果」（= Agent 当时看到的世界），不是「完整数据库」（= 世界完整真相）。内存重放对「商品后来下架/删除」免疫——因为不查真实库，用的是轨迹里冻结的那份结果。
- **重放初始状态冻结原则**：sandbox 真实执行时，初始数据必须「从轨迹回放读结果灌库」或「历史快照导入」，**绝不引用现在的活生产库**（活库会变：商品下架/订单流转/库存变）。若轨迹里连结果都没记录（脱敏丢失/截断/查询失败）→ 跳过该样本记 unknown，不补造。

## 实现回归校验（回归护栏，补齐「防退化」这半）

用户指出：重放校验只验证「失败 case 修好了」（上限/有效性），漏了「原能力没改坏」（下限/回归）。这是之前删 A/B 时一起删掉的「护栏」半。已实现：
- `internal/evolution/regression.go`（新增）：`RegressionCase/RegressionSet/RegressionCaseResult/RegressionReport` 类型 + `LoadRegressionSet`（SHA-256 哈希 + 校验）+ `RunRegression`（A 原版空 SkillSet / B 候选 SkillSet 交错跑，对比通过率）+ `concludeRegression`（三态：insufficient_coverage / regressed / not_regressed）。判定：B 通过率 < A → 退化；A=0 → 跳过（基准不成立）；无匹配用例 → insufficient_coverage。
- `tests/skill_eval/regression.json`（新增）：6 个典型能力样例（issue-triage 3 + purchase-advisor 3），每个含 input + fixture（State 格式）+ expect_tool（核心工具）。**不带安全类**（安全由架构保证，回归只测能力退没退化）。
- 集成：`run.go` 第 5 步（重放后，`--regression` 可选）+ `report.go` 的 `regressionReport` + `main.go` 的 `--regression` flag。结论合并 `regression=xxx`。
- 测试：`tests/skill_eval/evolution/regression_test.go` 7 例（加载/校验/三态/单 run 通过/缺失工具/端到端 not_regressed/覆盖不足）。

**真实模型冒烟（DeepSeek）**：`--evaluate-only --traces-file traces-detour.json --regression regression.json --trials 1` → 结论 `tool_reduced=1/1, regression=not_regressed`，3 个 issue-triage 用例 A=1/1 B=1/1 全通过无跳过。

**关键经验（expect_tool 要选「模型实际调用的工具」）**：coupon_query 用例起初 expect_tool=coupon_list，但模型对「我的优惠券」实际调 coupon_my_list（ListUserCoupons），导致 A 组基准不成立被 skipped。修正为 coupon_my_list + fixture 加 `claimed_coupons`（State 字段 json tag）后通过。写回归用例时 expect_tool 要让原 skill 稳定通过，否则会被 skipped。

**验证**：go build（不带 -o 成功；`-o .tmp/xxx.exe` 会被安全中心 SIGTERM，改用 go run 冒烟）、go vet、skill_eval 三包全绿。回归 = 重放校验的「对照组补集」，同一执行底座（WithSkillSet + evalrunner 模拟），只差用例来源与判定。
