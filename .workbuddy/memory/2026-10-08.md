## token 预算驱动的动态压缩实现（2026-10-08 晚）

用户需求：以 token 预算作为滑动窗口压缩（而非对话轮次），并明确"动态压缩 + 可压缩/不可压缩边界"。

**关键架构发现（重要）**：`contextmanager.Build` 是死代码（grep 确认仅测试引用）；真正的生产上下文组装路径是 `memory.CustomerServiceProvider.Retrieve`（经 eino `memoryMiddleware.BeforeModelRewriteState` 每次模型调用前触发）。之前几轮改的 contextManager.Build 滑动窗口是无效路径，真正的落地点在 CustomerServiceProvider。

**改动清单**：
- `domain/token.go`（新）：TokenBudget + HybridEstimator + EstimateTokens/TruncateToTokens（从 contextmanager 上移到 domain 共享层，避免 memory→contextmanager 倒置依赖）。
- `memory/customer_service_provider.go`：Retrieve 前置 `compressor.CompressIfNeeded`（每次模型调用前动态判断，超阈值才同步压缩）；`historyMessages` 从固定 12 条改为 token 滑动窗口（RecentWindowTokens 预算 + MinRecentMessages 保底）；工具调用（latest_tool_result/recent_tool_calls）加 token cap。
- `memory/provider.go`：新增 `Compressor` 接口 + `CompressCallback`。
- `contextmanager/summary.go`：`SummaryManager.CompressIfNeeded` 实现 Compressor；压缩循环从"攒30条压10条"改为"未压缩条数超过保留窗口（20）就压"（token 触发 + 条数兜底）。
- `config` + yaml：新增 TokenBudgetConfig，写死默认值（Total 8000 / RecentWindow 3000 / Summary 2000 / SummaryTrigger 4000 / SafetyFactor 0.9）。
- `svc/servicecontext.go`：接线 Compressor + OnCompressed（压缩后异步发布 Kafka 事件，避免画像/记忆提取失效）。

**边界**：只压缩 user/assistant 对话流 + tool 裁剪；长期事件/用户画像/system prompt/RAG 保持原样不压缩。

**调度**（用户确认）：裁剪兜底 + 同步摘要，但仅当上下文超阈值才触发摘要。

**测试**：domain/token_test.go、memory/customer_service_provider_test.go 新增；summary_test 45 条用例适配（压缩循环改为压到剩余 20 条，45 条从 2 轮变 3 轮）；`go test ./services/aiagent/...` 全绿。
