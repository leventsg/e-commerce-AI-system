## Agent MaxIterations 迭代耗尽兜底（final summary）

用户问：eino agent 达到 MaxIterations(8) 后迭代器处没有最后消息兜底。调研结论 + 实现如下。

### 框架调研结论（eino v0.9.14，v0.9.19 行为相同）
- `adk/react.go` ChatModel 节点 StatePreHandler：`st.getRemainingIterations() <= 0` 时直接 `return nil, ErrExceedMaxIterations`，**硬错误终止，无强制总结兜底**。
- `adk/handler.go:148` 注释明确：错误终止时 AfterAgent 钩子不会被调用（memory 收尾等失效）。
- 普通版与 agentic 版 react 图逻辑相同；turn_loop/runner 无相关兜底。
- 子 agent 耗尽时错误经 agent_tool.go `event.Err` 原样透传给 supervisor 迭代器。

### 项目实现（两层兜底）
1. **`services/aiagent/internal/eino/final_summary.go`（新增）**：`finalSummaryMiddleware`，挂在 root + 5 个子 agent 的 handlers 末尾。`BeforeModelRewriteState` 中通过 `compose.ProcessState` 读 `*adk.State.RemainingIterations`，==0（StatePreHandler 已递减，当前是最后一次模型调用）时：清空 `state.ToolInfos/DeferredToolInfos` + 追加 user 角色总结指令。模型物理上无工具可调，被迫输出文字总结。
   - 关键依据：`model.WithTools(nil)` → 空 slice → OpenAI 兼容请求不带 tools 字段；`populateToolChoice` 对空 tools + auto 不报错。
2. **`agent.go consumeEvents` 事件层兜底**：迭代器正常结束但 `hasAny && !hasAssistant` 时补发兜底 assistant_message（含 a2ui delta/done），写操作已执行时携带 `{"business_executed":true}`；补发前先 `failPendingToolCalls()` 关闭悬空工具 UI。
