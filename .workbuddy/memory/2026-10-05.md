# 2026-10-05 工作日志

## 整理《自进化系统技术说明》文档（技术实现细节沉淀）

用户连续追问自进化系统的技术实现细节，要求"工程师视角、讲实现原理、别给名词不解释"。逐轮澄清并回答了：

- **完整链路**（六阶段）：① 生产采集 → ② 读取轨迹 → ③ 分析 → ④ 生成候选 → ⑤ 双校验（重放+回归）→ ⑥ 证据报告。三个模型角色（分析/生成/被测）上下文隔离。
- **脱敏实现**（`Policy.Mode` 三种模式 + 四手段 + HMAC + 二次脱敏）：凭证正则、PII 正则、字段名黑名单、递归处理嵌套 JSON；UserID 用 HMAC-SHA256 伪名化；`privacyExporter` 对 status description + events 二次脱敏（MaskFunc 不覆盖 RecordError payload）。
- **Langfuse 接入的"框架自动 vs 手动埋点"边界（关键澄清）**：
  - 框架自动（Eino callback `langfuse.NewHandler`）只采 **Eino 框架层组件**：模型调用（ChatModel）、agent 委派（AgentTool）。
  - 手动埋点（`obs.Start/Event/Result/Correlate`）采的是**业务工具执行**（自定义 executor `tools/executor.go`）+ 确认 + RAG + 上下文组装。
  - **为什么业务工具要手动埋**：业务工具是自定义 `Executor.Execute` 执行的，绕开了 Eino callback，框架看不见，采不到参数/结果/业务结果，所以只能手动埋。
  - 手动埋点四类：① 工具执行链（tool.execution/handler.attempt/handler.started/tool.requested/guard.validation/guard.identity）② 确认链（confirmation.create/decision/user_wait）③ 会话知识库链（conversation.prepare/rag.retrieve/context.assemble）④ 关联标签 Correlate（run_id/checkpoint_id/tool_call_id/confirmation_id/source_trace_id 等）。
- **observation 是什么**：trace 下的子记录（对应 OTel span），字段 name/type/input/output/metadata；工具 observation 的 input=工具参数、output=工具返回结果，模型 observation 的 input=prompt、output=回复，全部脱敏后入库。
- **Langfuse 读取**：`LangfuseReader.FetchSessions` 调 REST `/api/public/traces`（分页）+ `/api/public/observations?traceId=xxx`，normalize 按 metadata.kind 组装成 SessionEvidence。

**产出**：`自进化系统技术说明.md`（项目根目录），整合完整链路 + Langfuse 接入（采集/读取）+ 脱敏 + 数据快照 + 候选生成 + 双校验 + 产物清单 + 边界，含"框架自动 vs 手动埋点"边界一节。
