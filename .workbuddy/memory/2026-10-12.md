## 上下文管理模块化重构（稳定前缀/易变后缀分离 + 三 Builder）
- **需求对齐**：① 稳定前缀注入角色——system prompt 用 system，其余（画像/事件）用带标签 user 消息；② 摘要放易变（压缩会改它）；③ RAG 移到易变、但 turn 内只检索一次；④ 稳定前缀缓存决策为 **ctx**（非 redis，因稳定前缀只剩画像+事件、体量小、查询便宜，redis 需 TTL+失效+多实例一致性，负优化）。
- **三模块划分**（都在 `internal/memory` 包，除 RAGBuilder 接口在 `internal/rag`）：
  - `MemoryBuilder`（memory_builder.go）：纯取数（近期对话/会话摘要/用户画像/长期事件），**不计算 token、不压缩**。
  - `ContextBuilder`（context_builder.go）：编排（摘要压缩 CompressIfNeeded + token 预算滑动窗口/各层 cap + 稳定/易变分层组装）。压缩能力在 ContextBuilder（用户拍板），MemoryBuilder 只读摘要结果。
  - `RAGBuilder`（rag/builder.go）：接口 `Prepare(ctx, PrepareRequest)`，`*rag.Service` 已实现（编译期断言 `var _ RAGBuilder = (*Service)(nil)`）；检索在 turn 入口 chatlogic 做一次，结果经 meta.RAGContext 传给 ContextBuilder。
- **稳定/易变分离**：稳定前缀（用户画像 + 长期事件）→ `RetrieveResult.SystemMessages`（注入 system prompt 后、history 前）；易变后缀（摘要 + 历史 + 任务状态 + 工具上下文 + 当前时间 + RAG）→ `HistoryMessages` + `ContextMessages`。稳定前缀字节 turn 内不变 → prompt cache 前缀可命中。
- **middleware 改造**（memory_middleware.go）：去掉旧的 `memoryPreparedContextKey` 整 turn 去重，改为 `memoryStablePrefixKey` ctx 缓存稳定前缀 + `RetrieveRequest.SkipStable`（首次 false 全量、后续 true 跳过稳定只刷易变）。每次模型调用前都触发压缩检查 + 易变刷新（诉求1：ReAct 中途动态压缩），稳定前缀 turn 内只查一次。
- **关键取舍**：historyMessages 拆成 filterAndSortHistory（MemoryBuilder，非 token）+ windowAndRedactHistory（ContextBuilder，token 滑动窗口+脱敏），原 historyMessages 保留为合并版供旧测试。CustomerServiceProvider 变薄门面（委托 ContextBuilder），保留 SearchUserMemoryEvents 供 capability 工具。TaskStates 字段现状 servicecontext 未装配（nil 跳过）。
